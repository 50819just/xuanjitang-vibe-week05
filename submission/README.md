## 發想動機
這個網站是為了朋友家人的傳統產業轉型而發想的。我想把原本較依賴電話與人工說明的服務流程，整理成可以先閱讀、了解價格，再提出預約需求的網站。以擇日館為主題，是希望保留傳統文化的特色，同時讓手機和電腦使用者都能更方便地操作。
目前是探索數位轉型的展示版本，不代表店家已正式採用，也不提供真實預約或收款。

## 規格文字說明
**目標對象**：想了解擇日／宅事服務、準備提出需求的人，以及希望了解數位預約流程的傳統業者。

**介面風格**：暖紙色、朱紅色、水墨插畫與書法意象，保留傳統文化氣氛，並使用清楚的標題、按鈕與分步表單。

**主要功能**：
1. **服務介紹**：首頁呈現7類服務；每項有詳情、適用情境、準備資料與參考價格。
2. **RWD響應式版面**：電腦呈現完整導覽與卡片；手機改用可開關的選單、單欄內容和易填寫的表單。
3. **四步預約申請**：需求 → 服務相關補充 → 聯絡／到場資料 → 摘要確認與同意。可回上一步，保留當次輸入。
4. **必填與錯誤提示**：沒有選服務、缺必要資料或未勾選同意會阻擋送出；後端再驗證，成功才顯示申請編號。
5. **費用確認示意**：輸入測試總價後，訂金依級距為800／1,200／1,600元；尾款為總價減訂金。尚未確認費用不能付款。
6. **綠界測試環境**：Node.js後端建立簽章，導向綠界官方測試付款頁；回站透過後端查單確認狀態，不用網址參數冒充付款成功。
7. **FAQ與知識文章**：常見問題可以展開／收合，並有3篇可閱讀的知識內容。網站不自動產生吉日或命理結果。
8. **單一HTML交付**：最終 `index.html` 內嵌CSS、JavaScript、圖片與SVG圖示，可瀏覽和操作；線上送出與付款需要網路及後端。

**技術與公開方式**：以React／Vite開發，再匯出單一HTML成品，透過GitHub Actions部署GitHub Pages。GitHub Pages本身只能放靜態網頁，不能執行綠界所需的後端API，因此另以Render部署獨立測試後端。

**互動操作路徑**：開啟首頁 → 查看服務 → 開始預約 → 填寫4步 → 確認摘要 → 送出測試申請 → 模擬確認總價 → 示意登入 → 綠界測試付款頁。

**驗收狀態**：已在公開網址實測完整表單送出、返回保留資料、必填防呆、手機選單、7個服務頁、3篇文章、價格與服務方式。Render可啟動，真實綠界查單回覆待付款狀態正常；程式檢查、13項自動測試及單檔建置通過。

本輪另於1440×900、390×844及320×844確認品牌導覽、提示與SVG圖示，並抽查價格、服務及知識頁的手機排版；這是針對性驗收，不代表所有頁面、所有裝置皆已完整巡檢。

**尚未完成的驗證**：目前停在綠界測試頁最終付款送出前；「刷卡完成、綠界實際通知、回站成功」尚未完整驗證，不宣稱已完成支付E2E。付款按鈕可抵達官方測試站，並非正式收款。

## 額外功能：綠界信用卡測試展示（非作業必要項目）
為了探索朋友家人傳統產業的數位轉型，本作品額外把 Render 測試後端與綠界官方測試環境串接。**請從上方 GitHub Pages 前台操作**；Render 的 `/api/health` 只顯示後端狀態 JSON，不是另一個前台網站，也不是付款入口。

### 操作步驟
1. 開啟 GitHub Pages → 選擇服務 → 開始預約。只用虛構資料，例如姓名「測試甲」、手機「0900000000」、地區「虛構測試地區」。
2. 填完四步、確認摘要及展示版資料使用說明，送出測試申請。
3. 在送出頁模擬確認總價 **5,000元**，畫面會顯示訂金 **800元**、尾款 **4,200元**。
4. 使用網站示意登入：Email **demo@xuanjitang.tw**、密碼 **demo1234**。這不是正式帳號，請勿使用個人帳密。
5. 按「支付預約訂金（Demo）」進入綠界測試付款頁；確認網域是 **payment-stage.ecpay.com.tw**、商品是「玄機堂擇日舘預約訂金」、金額 **NT$800**。
6. 如需自行試刷，選擇信用卡並使用以下測試資料；請勿輸入真實卡號、真實個資，也不要勾選記住付款人資訊。

## 與AI反覆調整的過程
- 先討論網站目的、服務範圍與預約流程，整理成完整規格。
- 發現原建置不是單一檔案，改為內嵌程式、樣式、圖片、字型，並檢查成品。
- 為GitHub Pages修正內頁與付款回站的hash導覽，避免內頁重整找不到檔案。
- 修正表單驗證、費用級距與付款狀態；補上偽造簽章、錯誤金額、模擬通知的拒絕測試。
- 真正在瀏覽器填寫預約、串接Render、進入綠界測試頁，再確認主動查單。
- 使用者指出舊手機防呆截圖內容被固定導覽遮擋，改為手機正常排版流、錯誤聚焦與自動捲回；390px及320px重驗後更新截圖。
- 手機QA發現320px頂部按鈕擠到選單，調整成小螢幕保留選單，預約入口仍在選單與內文。

- 接續使用者留下的視覺問題，發現桌機首頁仍有灰色透明導覽，統一為淡色品牌導覽；在公開網站重驗後更新桌機與手機截圖及QA文件。
